# osu! replay stream

Сервис для организации круглосуточного автоматического стрима osu!standard реплеев на Twitch и YouTube. Принимает `.osr` файлы, ставит их в очередь, рендерит видео через облачный сервис `o!rdr` или локальный `danser-go` и выводит результат через Browser Source в OBS Studio.

Поддерживает как **монолитный режим работы (standalone)** на одном ПК, так и **распределенную архитектуру (Main Controller + Render Worker)** через приватный VPN-туннель.

## Возможности

- **Веб-плеер для OBS** на `/` с бесшовным переходом между видео.
- **Панель управления** на `/control`: управление очередью, пропуск видео, регулировка громкости, переключение пресетов/загрузка фона ожидания и **раскрывающийся спойлер подключенных воркеров** с живыми характеристиками железа и прогрессом рендера.
- **Несколько источников реплеев**: заявки зрителей через Discord-бота со слэш-командами, ручная загрузка через браузер или папку `inbox/`, а также автоматический подбор случайных реплеев.
- **Два бэкенда рендера**: облачный [o!rdr](https://ordr.issou.best/) или высокопроизводительный локальный [danser-go](https://github.com/Wieku/danser-go).
- **Автоопределение системы для danser**: единый оптимизированный профиль `danser-stream.json` (пункт `[D]` в `configure.sh`), автоматически определяющий виртуализацию, число ядер CPU и доступность GPU-энкодеров (`nvenc` / `libx264`).
- **Расширенные метаданные**: отображение исполнителя, названия трека, сложности, звездности (★), ника игрока и модов в плеере и очереди.
- **Поддержка кастомных скинов**: автоматический выбор случайного скина для каждого реплея из коллекции.
- **Распределенная архитектура**: вынос ресурсоемкого рендеринга на удаленные ноды (воркеры) через WireGuard или Tailscale VPN.
- **Надежность и безопасность**: строгая атомарная очередь задач в SQLite, аренда задач с heartbeat, безопасный LRU-кэш карт и валидация через `ffprobe`.

## План развития (Roadmap)

- [x] **Распределенная архитектура Controller / Worker**: разделение контроллера и воркеров рендеринга с авторизацией по токенам и автовосстановлением зависших задач.
- [x] **Мониторинг воркеров и телеметрия в реальном времени**: спойлер в `/control` с детальными характеристиками железа подключенных воркеров (CPU, RAM, GPU, OS) и живым прогрессом рендеринга danser.
- [x] **Автоматическая адаптация профиля рендера**: определение типа окружения (VM / bare-metal) и подбор оптимального числа потоков без просадки основного сервера.
- [x] **Передача метаданных реплеев**: извлечение информации о карте и игроке воркером и отображение в плеере.
- [x] **Встроенный автономный вещатель (`stream_broadcaster`)**:
  - Прямой стриминг в RTMP через FFmpeg без необходимости держать открытым OBS и без видеокарты на контроллере.
  - Одновременный рестрим на Twitch и YouTube без повторного перекодирования (через `-c copy` с околонулевой нагрузкой на CPU).
  - Бесшовный экран ожидания (`tools/standby.mp4`) при пустой очереди или паузе стрима без разрыва RTMP-сессии.
  - Строгое соблюдение очереди через внутренние эндпоинты `/api/next` и `/api/complete`.
- [ ] **Headless-композитор оверлеев**: легковесный виртуальный композитор для наложения виджетов донатов и чата на сервере без графической оболочки.

## Протестированные аппаратные конфигурации

Кодовая база, пайплайн рендеринга и сетевой стек протестированы на реальном оборудовании:

| Характеристика | ПК на Linux (Основной / Разработка) | Ноутбук на Windows (Выделенный рендерер) | Cloud VPS (Выделенный Render Worker) |
|---|---|---|---|
| **Операционная система** | Arch Linux (Ядро `7.2.11-zen1-1-zen`, x86_64) | Windows 10 Pro (Сборка `19045.6480`, 64-bit) | Ubuntu 24.04 LTS (Ядро `6.8.0-generic`, x86_64) |
| **Процессор (CPU)** | Intel Xeon E5-2643 @ 3.30 GHz (4 ядра / 8 потоков) | AMD Ryzen 5 3500U with Vega Mobile Gfx (4 ядра / 8 потоков) | AMD Ryzen 9 5950X (выделено 4 vCPU) |
| **Оперативная память (RAM)** | 16 GiB DDR3 | 12 GiB DDR4 | 8 GiB RAM |
| **Видеокарта (GPU)** | AMD Radeon RX 550 / RX 560 (4GB VRAM) | AMD Radeon Vega 8 Graphics (Встроенная) | Paravirtual QXL (Software OpenGL) |
| **Бэкенд danser-go** | `0.12.1` (`stream-cpu` libx264 и `stream` VAAPI) | `0.12.1` (`stream-amf` Vega 8 и `stream-cpu`) | `0.12.1` (`stream-cpu` libx264 через Mesa llvmpipe) |
| **Скорость рендера** | ~1.8x–3.2x от реального времени | ~1.3x–3.6x от реального времени (AMF) | ~1.3x–1.76x от реального времени (LLVMpipe) |

## Быстрый старт

### Системные требования

- **Linux** или **Windows** (64-bit)
- **Python 3.10+** (проверено на 3.12 и 3.14)
- **FFmpeg и FFprobe** установлены и доступны в PATH
- **Драйверы с поддержкой OpenGL** (или программный рендерер Mesa LLVMpipe)

### Установка и настройка

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/divinity1437/osu-stream-bot.git
   cd osu-stream-bot
   ```

2. **Запустите мастер конфигурации:**
   ```bash
   ./configure.sh
   ```
   *(Или скопируйте `.env.example` в `.env` и настройте вручную).*

3. **Установите danser-go (если используется локальный рендеринг):**
   ```bash
   ./install-danser.sh
   ```

### Запуск стрима

- **Полный запуск (плеер + автонаполнение очереди):**
  ```bash
  ./run.sh
  ```
- **Запуск только веб-плеера (без рендера новых видео):**
  ```bash
  ./run.sh --no-producer
  ```
- **Автономный вещатель 24/7 (прямой RTMP стрим на Twitch и YouTube через FFmpeg):**
  ```bash
  ./run-broadcaster.sh
  # Или тестовый запуск без отправки на RTMP:
  ./run-broadcaster.sh --dry-run
  ```
- **Адреса интерфейсов:**
  - Веб-плеер: `http://127.0.0.1:8787/` (добавьте как Browser Source в OBS, если стримите через OBS)
  - Панель управления: `http://127.0.0.1:8787/control`
  - Проверка работоспособности: `http://127.0.0.1:8787/health`

### Тесты и проверка

```bash
# Запуск набора юнит-тестов (10 тестов)
pytest -v

# Проверка синтаксиса и корректности окружения
./check.sh

# Сквозной тест сетевого взаимодействия Controller + Worker
python smoke_test_e2e.py
```
